# 241 ワークスペース復元中・読み込み中の表示を整える

## 目的

起動・再読み込み時に、前回のワークスペースを復元している途中で「未選択」状態の画面（初回モーダル、空白画面）が一瞬表示される問題をなくす。復元・読み込みの途中であることが分かる表示にする。

## 難易度

- 判定: 中
- 理由: 変更箇所は`useWorkspaceSession`と`AppShell`、各モードの空状態表示に限られる。ただし、復元の開始・成功・失敗、復元設定OFF、復元途中のワークスペース選択という状態の組み合わせがあり、初回モーダルや復旧モーダルが出るべき場面で出なくなる回帰を起こしやすい。表示の一瞬のちらつきは、単体テストだけでは捉えにくい。

## 背景

2026-10-09のUI確認（dev server、ワークスペース復元ON）で以下を確認した。

- `/editor`を再読み込みすると、ワークスペースが復元される前に「小説ワークスペースを準備する」モーダルと、ヘッダーの「未選択」が一瞬表示される。
- `/chat`と`/reader`は、読み込み中のあいだ何も表示されない空白画面になる。ワークスペース未選択のチャットでも、空状態の案内が出るまでに空白の時間がある。

原因の見立て: `useWorkspaceSession`の`workspaceRestoreState`の初期値が`{ status: "idle" }`で、`restoring`へ切り替わるのはeffectの実行後になる。`AppShell.tsx`の`shouldBlockForWorkspace`は`restoring`のときだけモーダルを抑制するため、最初の描画でモーダルが出る。保存済みのワークスペースがあるかは`localStorage`から同期的に読めるので、初期stateの時点で`restoring`にできる見込み。ユーザー設定の「最後に開いたワークスペースを復元する」の読み込みタイミングも合わせて確認する。

## 対象範囲

1. 保存済みワークスペースがあり、復元設定がONなら、最初の描画から復元中として扱う。復元中は初回モーダルと「未選択」を出さない。
2. 復元中・読み込み中は、ヘッダーと各モード（チャット、エディット、リーダー）に、読み込み中であることが分かる控えめな表示（スケルトンまたはスピナーと短い文言）を出す。空白画面を残さない。
3. 復元に失敗したときは、現在どおり復旧モーダル（`mode="recovery"`）を出す。
4. 保存済みワークスペースがない、または復元設定がOFFのときは、現在どおり初回モーダル・空状態の案内をすぐ出す。
5. 必要なら`specs/novel-editor-mvp.md`の「ワークスペース選択」へ、復元中の表示を追記する。

## 対象外

- 復元の判定条件（検証API、保存キー）の変更。
- 初回モーダル自体の文言・構成の変更。

## 検証方針

- 先に失敗するテストを用意する。`App.test.tsx`などの結合テストで、保存済みワークスペースがあり検証APIの応答が未完了のとき、初回モーダルと「未選択」が描画されず、読み込み中の表示が出ることを確認する。現状はこのテストが失敗する見込み。
- 復元成功、復元失敗（復旧モーダル）、保存なし（初回モーダル）、復元設定OFFの既存の振る舞いが変わらないことをテストで確認する。
- Playwrightで、検証APIの応答を遅らせた状態で`/editor`を再読み込みし、初回モーダルが一度も表示されないことを確認する。
- 画面で、チャット・エディット・リーダーの読み込み中の表示を確認する。

## 完了条件

- [x] 復元中に初回モーダルと「未選択」が表示されない。
- [x] チャット・エディット・リーダーに、読み込み中の空白画面が残っていない。
- [x] 復元失敗・保存なし・復元設定OFFの振る舞いが変わっていない。
- [x] `bun run typecheck`、`bun run test`、`bun run test:e2e`が成功した。

## 実施結果

- 原因はSPAシェル（サーバー描画、localStorage不可）での初期state`idle`と、ルートチャンク読み込み中のOutletが空になることの2点だった。復元状態に`checking`を追加してmount後に確定させ、routerの`defaultPendingComponent`（遅延0ms）で読み込み表示を出すようにした。
- 復元中のヘッダーは「前回のワークスペースを開いています…」を表示し、手動パス入力は隠す。「ワークスペースを開く」は引き続き使える。
- `e2e/reader-editor-jump.spec.ts`は、必ず表示される開始ガイドを`isVisible()`の即時判定で閉じており、クリックがガイド取得に先行した場合だけ通る競合があった。読み込みタイミングの変化で顕在化したため、他のspecと同様にガイド既読キーを事前設定して決定的にした。
- 検証: `bun run typecheck`、`bun run test`（1224 passed）、`bun run test:e2e`（30 passed）。新規テストは実装前に意図した理由で失敗することを確認した（Vitest 4件、Playwright 1件。Playwrightの検出器は変更前のコードで初回モーダルと「未選択」の一瞬の表示を記録した）。検証APIを保留した状態で`/editor`・`/chat`・`/reader`のスクリーンショットを確認した。desktop検証は通信・ネイティブ境界を変更していないため未実行。
