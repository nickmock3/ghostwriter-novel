# 242 画面の文言・表示記号を揃える

## 目的

モードによって呼び方が違う文言、画面の状態と合わない案内文、英語と日本語が混ざった見出し、誤解されやすい表示記号を直し、画面全体の言葉と表示を揃える。

## 難易度

- 判定: 低
- 理由: 主に文言とCSSの変更で、データや保存処理に影響しない。ただし、文言を検索しているテストやPlaywrightのセレクターが多く、更新漏れで失敗しやすい。ヘッダーの新規作成ボタンはモードごとに挙動が違うため、文言を決めるときに仕様との整合を確認する必要がある。

## 背景

2026-10-09のUI確認で以下を見つけた。

| 箇所 | 現状 | 問題 |
| --- | --- | --- |
| ファイルツリーの開いているファイル（`src/styles/file-tree.css`の`.file-tree-row[aria-current="true"] .file-tree-row-label::after`） | ファイル名の右に黒丸を表示 | VS Codeなどでは黒丸は「未保存」を表すため、保存済みでも未保存に見える |
| サイドバー（`src/app/AppShell.tsx`） | 「チャットモード」「エディット画面」「リーダーモード」 | 3つのモードの呼び方が揃っていない |
| ヘッダーの新規作成ボタン（`src/features/workspace/WorkspaceBar.tsx`） | チャットでは「新しい小説を始める」、エディットでは「新規ワークスペース」 | 同じ位置のボタンの名前がモードで変わる |
| チャット入力欄の案内（`src/features/ai-chat/ChatPane.tsx`） | 「ワークスペースについて質問」 | 小説を書き進めるチャットの用途と合っていない |
| エディターの空状態（`src/features/editor/EditorPane.tsx`） | ワークスペースを開いていても「ワークスペースを選択し、テキストファイルを開くと…」 | 画面の状態と合っていない |
| 見出し・状態表示 | 「EXPLORER」（`FileTreePane.tsx`）、「AI Chat」（`ChatPane.tsx`）、「Plain Text」「Saved」「Unsaved」（`EditorPane.tsx`） | 他の日本語UIと混ざっている |

ヘッダーの新規作成ボタンについて: 仕様上、チャットモードは「フォルダ選択とチャット用テンプレート適用を1つの流れに畳んだ導線」、エディットモードは「テンプレートを選んで新規ワークスペースを作る」導線で、挙動が意図的に違う。文言を完全に同じにすると挙動の違いが分からなくなるため、統一ではなく「同じ系統の言葉で、違いが分かる名前」にする（例: 「新しい小説を始める」と「テンプレートから新しい小説を作る」）。

## 対象範囲

1. ファイルツリーの開いているファイルの黒丸をやめ、背景色と太字だけで示す。未保存の表示を別途出す場合は、エディターの未保存状態と一致させる。
2. サイドバーの呼び方を「チャットモード」「エディットモード」「リーダーモード」に揃える（`aria-label`、`title`、表示文言）。`router.tsx`、`ReaderPage.tsx`の「エディット画面へ…」の導線文言も合わせる。
3. ヘッダーの新規作成ボタンの文言を、上記の方針で決めて変更する。
4. チャット入力欄の案内を、小説を書き進める用途に合う文言にする（例: 「書きたいこと、相談したいことを入力」）。ワークスペース未選択時の案内は現状のままでよい。
5. エディターの空状態を、ワークスペース未選択とファイル未選択で出し分ける（例: 「左のツリーからファイルを選ぶと、ここで編集できます」）。
6. 「EXPLORER」「AI Chat」「Plain Text」「Saved」「Unsaved」を日本語にする（例: 「ファイル」「AIチャット」「プレーンテキスト」「保存済み」「未保存」）。
7. 仕様に画面上の呼び方の記述があれば、`specs/novel-editor-mvp.md`も合わせる。仕様文中の「エディット画面」（画面・ルートの呼び方）は、UIの表示文言とは別に扱ってよい。

## 対象外

- ボタンを押したときの挙動・導線の変更。
- AIアシストのペイン構成（243）、チャットの初期案内の操作化（244）、細部の切り詰め・設定画面の調整（245）。

## 検証方針

- 文言の変更は実装を写したテストになりやすいため、文言を確認するだけの新規テストは追加しない。既存テスト・Playwrightのセレクター（`getByRole`の名前、`getByText`など）を新しい文言へ更新し、すべて成功することで確認する。
- エディターの空状態の出し分け（ワークスペース未選択 / ファイル未選択）は挙動の変更なので、`EditorPane`のテストで2つの状態の表示を確認する。先に失敗するテストを用意する。
- 黒丸の削除はCSSのみの変更のため、画面で確認する。
- 画面で、チャット・エディット・リーダー・サイドバーの文言が揃っていることを確認する。
