# 244 チャットの新規会話の案内に、押せる候補を付ける

## 目的

新規会話の案内に並ぶ「アイデア出し」「設定やプロットの整理」「本文の執筆・推敲」を、押すと入力欄に依頼文が入る候補ボタンにする。何を頼めばよいか分からない最初の一歩を軽くする。

## 難易度

- 判定: 中
- 理由: UIの追加は`ChatPane`と`ChatComposer`の範囲に収まる。ただし製品仕様（チャットモードの新規会話の案内）の変更を伴い、入力欄の既存の内容・添付チップとの関係、送信まで自動で行うかどうかの判断が必要になる。

## 背景

2026-10-09のUI確認で、新規会話の案内（`src/features/ai-chat/ChatPane.tsx`の`emptyConversationCopy`）が文章だけで、操作につながっていないことを確認した。仕様では「新規会話の案内は初回メッセージの送信前だけ表示し、最初のターンを開始した時点で非表示にする」と定めている。

## 対象範囲

1. 案内の下に、3〜4個の候補ボタンを表示する（例: 「物語のアイデアを一緒に考えて」「登場人物と世界観を整理して」「第1章の本文を書き始めたい」「書いた本文を推敲して」）。
2. 候補を押すと、入力欄へ依頼文を入れてフォーカスする。自動送信はしない（ユーザーが内容を直してから送れるようにする）。
3. 入力欄にすでに文字がある場合は上書きしない（末尾に追記するか、候補を押せなくする。どちらにするか実装開始時に決めて作業記録へ残す）。添付チップは変更しない。
4. 案内と同じく、最初のターンを開始したら候補も非表示にする。ワークスペース未選択・実行中は表示しない（現在の`emptyConversationCopy`と同じ条件）。
5. `specs/novel-editor-mvp.md`の「チャットモード」に、候補ボタンの振る舞いを追記する。

## 対象外

- 候補の内容をワークスペースの状態（章の有無など）に合わせて変えること。
- 候補の追加・編集をユーザーが設定できるようにすること。

## 検証方針

- 先に失敗するテストを用意する。`ChatPane`のテストで、候補を押すと入力欄に依頼文が入り、送信はされないことを確認する。
- 入力欄に文字がある場合の振る舞い（上書きしない）をテストで確認する。
- 最初のターンを開始すると候補が消えることを確認する。既存の案内の非表示テストがあれば、候補も含めて確認するよう更新する。
- 画面で、候補の見た目と入力欄へのフォーカスを確認する。

## 完了条件

- [ ] 新規会話の案内に候補ボタンが表示され、押すと入力欄に依頼文が入る。
- [ ] 自動送信されず、入力中の文字を上書きしない。
- [ ] 最初のターン開始後、ワークスペース未選択時、実行中には表示されない。
- [ ] 仕様を更新した。
- [ ] `bun run typecheck`、`bun run test`、`bun run test:e2e`が成功した。
