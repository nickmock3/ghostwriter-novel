# チャットの状態と画面の寿命を分ける

## When this matters

チャットのバックグラウンド実行、画面遷移、エディター選択文のチャットへの引き渡しを変更するとき。

## Field note

Reactの画面をアンマウントしても非同期の送信処理は自動停止しない。一方、その画面内のstateは新しい画面インスタンスへ引き継がれない。通信の継続だけを確認しても、復帰後の表示が継続する保証にはならない。

controllerをルートより長寿命にすると、入力文と同様に「選択文の追加要求を処理済みか」も長寿命にする必要がある。画面のeffectだけで要求を処理すると、復帰時に同じ選択文をもう一度追加してしまう。

## Reliable procedure

- 送信を保留したまま別ルートへ移動し、復帰前後で応答を解放して結果を確認する。
- ストリームの途中表示は、完成済みNDJSONを返すだけではなく、ReadableStreamへ別々のタイミングでdeltaと最終会話を投入して確認する。
- 追加要求IDはcontroller側で保持し、表示側の再マウントで再処理しないことを、ユーザーが編集した入力文の維持で確認する。
- ワークスペース切替は古い応答の完了を遅延させ、新しいセッションに通知と結果が混ざらないことを確認する。

## Failure signals

戻ると応答が止まって見える、送信ボタンが再び有効になる、選択文が入力欄に二重追加される。

## Recheck when

ルート構成、チャットcontrollerの配置、ワークスペースセッションの保持範囲を変更したとき。
