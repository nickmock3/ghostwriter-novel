# Agent Field Guide

Agent Field Guideは、エージェントが実作業中に得た、次のエージェントの試行錯誤を減らすための経験知を残す場所です。

製品仕様、必須ルール、未完了作業の管理場所ではありません。

- 製品として守る要件は`specs/`へ記載する。
- 常に守る開発ルールは`AGENTS.md`または`specs/development-workflow.md`へ記載する。
- 未完了の作業は`tasks/open/`へ記載する。
- Field Guideには、コードや仕様だけでは気づきにくい、再利用可能な現場知を記載する。

## 参照方法

作業開始時は`INDEX.md`だけを確認し、現在の作業に関係するエントリーだけを読みます。すべてのエントリーを毎回読む必要はありません。

索引で見つからない場合は、`rg`で`agent-field-guide/entries/`を検索します。

## 記録するもの

次の条件を満たす知見を記録します。

- 知らないと同じ失敗や遠回りを繰り返す可能性がある。
- 今回限りではなく、将来の作業でも利用できる。
- 原因、成功した手順、失敗の兆候のいずれかを具体的に説明できる。
- 仕様やコードを普通に読むだけでは見つけにくい。

例:

- Cursor CLIへ委任するときに必要な呼び出し方や依頼の境界。
- 開発時と配布時で異なるデスクトップ実行環境の挙動。
- 一見無関係な変更で壊れやすい検証手順。
- 特定の失敗を早期に見分けるための兆候。

一度だけ発生した原因不明のエラーや、未確認の推測だけのメモは記録しません。推測を残す必要がある場合は、Field Guideではなく調査タスクやissueとして扱います。

## 追加・更新方法

1. `INDEX.md`と`entries/`を検索し、同じ知見がないか確認する。
2. 同じ知見があれば既存エントリーを更新する。
3. なければ`ENTRY_TEMPLATE.md`を基に、`entries/`へ1知見1ファイルで追加する。
4. `INDEX.md`へ、読むべき状況、要点、エントリーへのリンクを1行で追加する。

ファイル名は日付や連番を付けず、`cursor-delegation-non-interactive-mode.md`のように内容を表すkebab-caseを使います。

Field Guideの追加だけを目的とするタスクは不要です。実装タスク、調査、ツール委任など、知見を得た作業の一部として直接更新できます。関連するタスク、issue、commitがある場合はエントリーへ任意で記載できます。

## 保守方針

- 日付、status、confidenceなど、継続的な更新が必要なメタデータは必須にしない。
- 外部ツールのバージョンが知見の成立条件に関係する場合だけ、本文へ具体的に記載する。
- 古くなった内容は、その領域を触ったエージェントが更新または削除する。履歴はGitで確認する。
- コードパスや行番号は陳腐化しやすいため必須にしない。必要な場合は、現在の探索を助ける任意情報として記載する。
- 必須ルールや製品要件になった知見は`AGENTS.md`、`specs/`、テストへ昇格し、Field Guideとの重複を残しすぎない。
- APIキー、認証情報、個人情報、ローカル環境固有の機密情報は記載しない。
