2026-10-05時点の作業ツリーを、Git履歴を持ち越さず別リポジトリへ公開する前提で確認した。コード・仕様・テストを残し、個人情報やローカル生成物だけを整理するための記録である。

**監査で検出した個人絶対パス2文書・4箇所と、環境ファイル等の除外設定の不足は修正済み。** 公開者名・Store識別子はユーザーの判断により現状維持とする。調査範囲では実メールアドレス・実APIキー・秘密鍵の追跡ファイルへの混入は見つからなかったが、秘密情報が存在しないことを網羅的に証明する監査ではない。

## 公開直前の確認手順

1. 個人パス4箇所とignore不足は修正済み。コード・仕様・テストは維持する。
2. Store公開者情報・著作権者表記・製品URLはユーザー決定により現状維持する。
3. 新しいディレクトリへレビュー済み追跡ファイルだけを移し、旧`.git`やローカルデータを含めずに初期化する。
4. `git ls-files`と`git status --short`で初回公開対象を確認し、環境ファイル、秘密鍵、ログ、生成物がないことを確認する。新規ファイルはstage前の一覧も確認する。
5. 新repoの内容に対して個人パス・メール・秘密情報の検索を再実行する。監査後の追加ファイルや新たなcommit作者情報も対象にする。見つかった実秘密情報はレポートへ転載せず、含まれた場合は失効・再発行を判断する。
6. 公開用作者設定とライセンス・noticeを確認してから初回commitする。配布binaryを公開する場合の埋込みパスやデバッグ情報は、ソース監査とは別にそのartifactを対象として確認する。
